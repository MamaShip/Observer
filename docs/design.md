## 1. 背景与目标

### 1.1 背景

Observer（折光观察者）是一个微信公众号文章备份与删除监测服务：用户提交文章链接，系统立即备份，并在观察期内定期检查文章是否仍可访问，文章失效时通知用户。

旧实现（2020 年，2022 年停服）存在以下根本问题，因此整体重写而非修补：

- 运行时与依赖老化：Python 3.5–3.8、依赖未锁定，按现有依赖安装已无法启动。
- 可靠性：工作线程遇到未捕获异常会静默退出，观察/发信停止且无告警。
- 正确性：删除检测依赖 2020 年的页面结构；被反爬拦截时会被误判为"文章存在"。
- 通知渠道失效：Gmail 已停用账号密码 SMTP 登录。
- 无测试、无部署自动化、配置与个人信息硬编码在代码中。

### 1.2 目标

1. **独立核心服务**：业务逻辑与入口解耦，对外提供统一 JSON API；Web 与订阅号是入口，未来接入小程序时不改核心。
2. **HTML 备份**：每篇文章保存清洗后的 HTML 快照与图片；用户可在线查看、下载单文件 HTML，或通过浏览器打印为 PDF（阅读版自带打印样式）。
3. **账号体系**：邮箱登录，用户在 Web 上管理观察列表、查看备份。
4. **邮件通知**：文章被删除时发邮件，邮件内附查看链接（不带附件）。
5. **检测可信**：明确区分"存在 / 已删除 / 被拦截 / 网络错误"，宁可报告"无法判定"也不误报漏报。
6. **低成本、低维护**：单台小规格 VPS 运行；除已有资源外新增现金成本为零；单二进制部署，依赖锁定，自动化测试与部署。

### 1.3 非目标

- 小程序入口、微信消息推送（无企业主体，见 §2）。
- 被审查文章的全量备份（定位是个人关注文章的备份）。
- 多机部署 / 高可用。

## 2. 约束

| 类别 | 约束 | 对设计的影响 |
|---|---|---|
| 主体 | 无企业主体 | 无法使用服务号模板消息/订阅通知、开放平台 UnionID、微信扫码登录 → 通知只用邮件，登录用邮箱 |

## 3. 总体架构

```
                      ┌──────────────────── VPS（Docker Compose）─────────────────────┐
                      │                                                              │
  浏览器 ──HTTPS──▶ Caddy ──┬── <domain>        ──▶ app: API + 内嵌 Web 静态文件        │
                      │     └── snap.<domain>   ──▶ app: 快照服务（隔离域，无登录 Cookie）│
  微信 ───HTTPS──▶ <domain>/wechat/callback ──▶ app: 订阅号被动回复                     │
                      │                      ┌────────────────┐                      │
                      │                      │ app（单 Go 进程）│                      │
                      │                      │  ├ HTTP 层 (Huma)│                      │
                      │                      │  ├ River workers │                      │
                      │                      │  └ 周期任务      │                      │
                      │                      └───┬─────────┬───┘                      │
                      │                          │         │ 本地磁盘缓存（上限 5 GB）  │
                      │                   Postgres 18      │                          │
                      │              （业务数据 + 任务队列） │                          │
                      └──────────────────────────────────── │ ─────────────────────────┘
                                                            ▼
                     mp.weixin.qq.com / mmbiz.qpic.cn    Wasabi（快照、图片、DB 备份）
                                                         Resend SMTP（邮件）
                                                         Healthchecks.io（心跳告警）
```

### 3.1 进程模型

一个 Go 二进制 `observer`，`serve` 在同一进程里运行 HTTP 服务、任务 worker 和周期任务；将来如需拆分，可通过参数让 API 与 worker 分别运行。其余子命令（`migrate`、`admin`、`probe`、`netcheck`、`mailtest`、`mpsim`、`openapi`、`healthcheck`）见 [development.md](development.md#命令行工具与配置)。`healthcheck` 请求本机 `/api/v1/healthz`，供 Docker `HEALTHCHECK` 使用。

### 3.2 模块划分

| 包 | 职责 |
|---|---|
| `internal/wechat` | URL 识别与规范化、页面抓取、解析、删除检测（**核心难点，测试覆盖要求最高**） |
| `internal/snapshot` | HTML 清洗、图片下载与去重、生成阅读版 HTML（含打印样式）、生成单文件 HTML |
| `internal/watch` | 业务核心：提交、观察、状态机、调度策略、续期（不依赖 HTTP 与具体存储） |
| `internal/auth` | 邮件验证码、会话、邀请、公众号绑定、限流 |
| `internal/notify` | 决定发什么邮件、何时发：摘要合并、额度、告警 |
| `internal/mail` | Mailer 接口、SMTP 实现、邮件模板 |
| `internal/mp` | 订阅号被动回复：签名、XML、消息与回复（§6.7） |
| `internal/jobs` | River 任务与周期任务：薄 worker，调用 `watch` / `notify` 等 |
| `internal/api` | HTTP handler（Huma），生成 OpenAPI 文档 |
| `internal/snapserver` | `snap.<domain>` 快照与资源服务 |
| `internal/webui` | 内嵌前端（`dist/app` 由 `make web` 生成，不进 git） |
| `internal/blob` | Wasabi（S3）读写 + 本地磁盘 LRU 缓存 |
| `internal/store` | Postgres 访问（sqlc 生成）、迁移文件 |
| `internal/backup` | 每日 `pg_dump` 到对象存储、恢复 |
| `internal/app` | `serve` 的组装：连接、迁移、worker、HTTP、优雅退出 |
| `internal/config` | 环境变量配置 |
| `internal/probe`、`internal/netcheck` | 诊断工具 `observer probe` / `netcheck` |
| `web/` | Vue 3 前端 |

依赖方向：`api / jobs / mp → watch、auth → (wechat, snapshot, store, blob, mail 的接口)`。业务规则放在服务层（`watch`、`auth`）的事务里，HTTP 处理函数只负责校验输入、翻译错误。

## 4. 技术栈

| 层 | 选择 | 理由 / 备选 |
|---|---|---|
| 后端语言 | **Go**（当前稳定版） | 兼容性承诺强、单静态二进制、内存占用低、并发原生 |
| HTTP / API | 标准库 `net/http` + **Huma v2** | 代码即契约，自动输出 OpenAPI 3.1，供前端与未来小程序生成类型 |
| 数据库 | **Postgres 18** | 自带 `uuidv7()`；同时承载任务队列 |
| DB 访问 | **pgx v5 + sqlc** | 手写 SQL，生成类型安全代码，不用 ORM |
| 迁移 | **goose** | SQL 文件迁移，启动时自动执行（advisory lock 防并发） |
| 任务队列 / 调度 | **River** | Postgres 原生：重试、唯一任务、周期任务、事务内入队、Snooze；不需要 Redis |
| 抓取 | `net/http`（自动 gzip）+ **goquery** | 微信文章结构固定，无需通用 readability |
| PDF | **浏览器打印**（阅读版内置 `@media print` 样式） | 服务器零开销；如以后需要服务端直出 PDF，用纯 Go PDF 库按快照结构排版，不引入浏览器 |
| HTML 清洗 | **bluemonday** | 白名单清洗 |
| 对象存储 | **minio-go**（S3 兼容） | 对接 Wasabi，API 比 aws-sdk 轻 |
| 邮件 | **wneessen/go-mail**（SMTP）→ Resend SMTP | 走标准 SMTP，换服务商只改配置 |
| 配置 | `caarlos0/env` | 环境变量 → 结构体 |
| 日志 | `log/slog`（JSON → stdout） | Docker 负责日志轮转 |
| 限流 | `golang.org/x/time/rate` | 单实例内存令牌桶足够 |
| 前端 | **Vue 3 + Vite + TypeScript** + vue-router | 构建产物 `go:embed` 进二进制 |
| 前端 API 类型 | `openapi-typescript` + `openapi-fetch` | 由后端 OpenAPI 自动生成，避免手写类型 |
| 前端样式 | 原生 CSS（不引入组件库） | 页面少，减少依赖与升级负担 |
| 反向代理 / TLS | **Caddy 2** | 自动申请/续期 Let's Encrypt 证书 |
| 编排 | **Docker Compose** | 3 个容器：caddy / app / postgres |
| CI/CD | GitHub Actions + **GHCR** | lint、测试、构建镜像、tag 触发部署 |
| 监控 | `/healthz` + **Healthchecks.io** 心跳（免费） | 任务停摆、金丝雀失败时邮件告警 |

> Node.js 只在构建前端时使用（本地与 CI），不进入运行时。浏览器只在开发者本机用于调试与验收，不部署到服务器。

## 5. 领域模型

### 5.1 核心概念

- **Article（文章）**：全局唯一的一篇微信文章。多个用户提交同一篇文章时只抓取、只检查一次。
- **Snapshot（快照）**：某一时刻文章内容的备份。目前每篇文章在首次成功抓取时生成一份（管理员可重新备份）；未来可在检测到内容变化时追加。
- **Asset（资源）**：快照引用的图片，按 sha256 内容寻址去重。
- **Watch（观察）**：某用户对某文章的观察关系，有自己的观察期与结束原因。
- **CheckRun（检查记录）**：每次检查的结果，用于排障与统计。

### 5.2 文章标识与去重

微信文章链接有多种形态，例如短链 `https://mp.weixin.qq.com/s/<token>`、长链 `https://mp.weixin.qq.com/s?__biz=..&mid=..&idx=..&sn=..&<追踪参数>`。

1. **提交时预规范化**：仅接受 `mp.weixin.qq.com/s` 开头的链接；短链去掉 query 与 fragment；长链的别名 key 只保留 `__biz, mid, idx, sn`（按固定顺序），**但请求地址要保留 `chksm`**：长链缺少 `chksm` 时微信一定会返回验证页，带上任意值（包括占位值 `00000000`）就能正常访问，所以用户给的长链没有 `chksm` 时直接带占位值请求（`Link.ServiceFetchURL`）。临时链接（带 `timestamp` 和 `signature`）会过期，直接拒绝。结果写入 `url_aliases` 查重。
2. **抓取后确定规范 ID**：从页面脚本变量 `biz, mid, idx, sn` 得到 `canonical_key = biz:mid:idx`；若已存在同 key 的文章，则把新别名并入已有文章。之后的检查一律使用页面中的 `msg_link`（即短链）作为请求地址。
3. 实现见 `internal/wechat`（`link.go`、`analyze.go`）。

### 5.3 文章状态机

```
            首次抓取成功                     确认删除（两次检查一致）
 pending ───────────────▶ alive ────────────────────────────▶ deleted（终态）
    │                       │
    │ 首次抓取即判定删除/无效   │ 无活跃观察
    ▼                       ▼
 invalid（终态）          dormant（停止检查；有新观察时回到 alive 并恢复调度）
```

- **检查结果**有五种：`alive` / `deleted(原因)` / `invalid`（参数错误、链接过期）/ `blocked`（验证码、环境异常、被限流）/ `error`（网络、5xx、解析失败、无法识别的页面）。
- 只有 `alive`、`deleted`、`invalid` 会改变文章状态；`blocked` 和 `error` 只累加 `consecutive_failures` 并退避重试，连续超过阈值（默认 6 次）触发告警。
- **删除需确认**：首次判定为 `deleted` 后，10 分钟后再检查一次，两次一致才进入 `deleted`。确认时在事务内锁住文章行、核对当前状态和首次判定时间：间隔不足 10 分钟的检查（如管理员手动触发）不算确认，只把下次检查定在首次判定后 10 分钟。文章从 `dormant` 恢复时清掉之前的首次判定，因为中间可能恢复过。
- 删除原因原样记录页面提示文字，并映射到分类：`author_deleted`（作者删除）、`violation`（违规）、`complaint`（被投诉）、`account_blocked`（账号封禁/迁移）、`unknown`。

### 5.4 观察状态机

```
 resolving ──▶ active ──┬──▶ ended(deleted)        文章被删 → 邮件通知
    │                   ├──▶ ended(expired)        观察期满 → 不发邮件
    │                   └──▶ ended(user_stopped)   用户主动停止
    └──▶ failed(invalid)   提交的链接无法解析或首次即不可访问
```

- 默认观察期 **60 天**（配置项 `WATCH_DAYS`），可续期（§6.5）。
- 同一用户对同一文章只允许一个 `active` 观察。
- 观察结束后，用户仍可查看该文章的快照（快照归属文章，访问权限来自"曾经观察过"）。

### 5.5 检查调度策略

文章的 `next_check_at` 根据其首次入库后的时长决定：

| 文章入库时长 | 检查间隔 |
|---|---|
| 不满 24 小时 | 3 小时 |
| 满 24 小时、不满 7 天 | 8 小时 |
| 满 7 天 | 24 小时 |

- 每次在间隔上加 ±20% 随机抖动，避免集中请求。
- 全局抓取限速：同一时刻最多 1 个抓取请求，两次请求最少间隔 3 秒（`FETCH_MIN_INTERVAL`）。
- 遇到 `blocked`：指数退避（5 分钟起，上限 2 小时）；短时间内多篇文章都被拦截时触发**全局熔断**，暂停所有抓取 30 分钟。
- 文章没有活跃观察时进入 `dormant`，停止检查。
- 一个周期任务（每分钟）领取 `next_check_at <= now()` 的文章并入队检查任务；River 的唯一任务机制保证同一文章不会重复排队。

**容量估算**按串行 3 秒一次计算，理论上限为每小时 1200 次。若文章都在首日，每篇每 3 小时检查一次，对应约 3600 篇同时观察的文章。

**流量估算**：正文页解码后约 4 MB，gzip 后约 880 KB。定期检查不下载整页，有两种读取方式：

| 检查方式 | 读到哪里为止 | 实测每次流量 | 60 天约 79 次（8 + 18 + 53） |
|---|---|---|---|
| `check`：确认正文节点存在 | `#js_content` 之后 64 KB | ~210 KB | ~17 MB |
| `head`：只读页面头部（实验性） | Open Graph 标签 | ~26 KB | ~2 MB |
| 已删除、验证页 | 页面本身很小 | ~16 KB | — |

另外，首次快照（整页加图片下载，再上传 Wasabi）约 10 MB/篇。全部使用 `check` 约 27 MB/篇；500 GB 月流量扣除为用户查看预留的约 200 GB 等，大约能支撑每月 1 万篇新文章。

- **目前全部用 `check`**。删除页和验证页都没有 Open Graph 标签，`head` 的前提成立，但还缺侵权投诉、封号样本；样本齐全后再决定是否用 `head` 做日常检查、每天用 `check` 复核一次（约 25 MB/篇）。

### 5.6 通知策略

- **文章被删除**：周期任务每 5 分钟扫描一次"已结束但未通知"的观察，按用户合并成一封摘要邮件（同一用户这段时间内的多篇删除只发一封）。用扫描而不是每次删除单独入队，任务失败或并发时都不会漏发。
- **观察期满**：不发邮件，只在文章被删除时发邮件。观察到期时直接标记为已通知；网站上照常显示"已到期"，备份保留。
- 邮件只包含标题、状态、删除原因和**查看链接**，不带附件。
- **每日发送上限保护**：Resend 免费档每日 100 封（`DAILY_EMAIL_LIMIT`）。通知和邀请邮件只用到额度的 90%，剩下 10% 留给验证码邮件。通过公共邀请链接请求的验证码（邮件类型 `join`）另有每日预算：最多占额度的 30%，全站用量到 90% 时也停止发送，超出时接口返回 503"今天通过邀请链接发送的验证码已达上限"，普通登录和通知不受影响。发送遇到限额（本地计数或服务商返回）时，摘要和邀请任务顺延到次日 UTC 零点之后。当日发送量达到 80% 时给管理员发告警。
- **每个账号每月最多 20 封通知邮件**（`MONTHLY_EMAIL_LIMIT`，按北京时间自然月计）：只计删除通知邮件，验证码、邀请与管理员告警不计。达到上限后摘要任务顺延到下月 1 日 00:05，届时把这期间的全部变化合并成一封；第 20 封邮件里会说明已达上限。每个账号可单独设置上限（`users.monthly_email_limit`，空值用默认值，0 表示不限），为以后付费提高上限预留：`observer admin email-limit <email> <n|default>`。设置页显示"本月已收到 X / 20 封"。
- **验证码邮件同步发送，不进任务队列**：任务参数以明文存在 `river_job` 表里，验证码不能明文落库。额度用完时，登录接口直接返回 503"今天的邮件发送额度已用完"。
- **管理员告警**（`ADMIN_EMAILS`）：金丝雀失败、熔断打开、单篇文章连续 6 次检查无结论、邮件用量达到 80%、数据库备份失败。同类告警 6 小时内只发一次，并且都会写入错误日志。

## 6. 关键流程

### 6.1 登录（邮箱验证码）

1. 用户在登录页输入邮箱 → `POST /api/v1/auth/code`，服务端发送 6 位数字验证码（标题里也带验证码，手机通知栏可直接看到）。
2. 验证码只存哈希，10 分钟有效，一次性使用；每个验证码最多尝试 5 次，只有最近一次发送的验证码有效。
3. 用户在**同一页面**输入验证码 → `POST /api/v1/auth/verify {email, code}`。
4. 验证成功：首次登录则创建用户（开放模式，或邀请制下通过公共邀请链接，见下文）；签发会话 token（256 位随机数，哈希存库，60 天滑动过期：每次使用时、最多每小时一次把服务端过期时间延后到 60 天后，并重新下发同样有效期的 Cookie，否则浏览器会在登录 60 天后丢掉 Cookie），写入 `__Host-session` Cookie（`Secure; HttpOnly; SameSite=Lax`）。
5. 发送限制：
   - **每个邮箱每天最多 2 封**（按北京时间自然日），两次之间至少隔 60 秒。用完后接口返回 429"这个邮箱今天已获取过 2 次验证码，请明天再试"。
   - 同一 IP 每小时最多 10 次。
   - 计数对所有邮箱一视同仁（无论是否有账号、是否被邀请、是否停用），响应也相同，不泄露邮箱是否注册。发信失败时退还这次计数。
   - 接口返回当天剩余次数和可重发的等待秒数，供前端显示倒计时。

**日常登录采用验证码而不是魔法链接的原因**：
- 用户多在手机浏览器或微信内置浏览器里使用本站，而邮件常在 QQ 邮箱等 App 里看；点链接会在邮件 App 的内置浏览器里登录，回到原页面仍是未登录。验证码在原页面输入，登录就发生在原浏览器里。
- 每天只有 2 次机会，魔法链接"登录到了错误的浏览器"会白白浪费一次。
- 不受邮件安全扫描器预取链接的影响；国内用户也更熟悉验证码。
- 代价：6 位验证码靠尝试次数保证安全（每天最多猜 10 次，命中概率约十万分之一），可以接受。

**邀请**（邀请制下）：只有已有账户的邮箱能收到验证码，所以"邀请"就是为这个邮箱建好账户。
- 用户在设置页填写对方邮箱即可邀请，**每人每月 5 个**（北京时间自然月，`MONTHLY_INVITE_LIMIT`，0 表示只有管理员能邀请）；管理员不限，也可以在后台账户页或用 `observer admin invite` 邀请。
- 设置页、管理后台和命令行都会自动为尚未首次登录的有效账户发送邀请邮件，提供纯文本和 HTML 两种格式。收件人点击邮件中的链接，在打开的页面上再点「接受邀请并注册」，浏览器即为该邮箱完成首次登录，进入「我的观察」。打开链接本身不兑换令牌，以免会执行脚本的邮件安全扫描器用掉链接并拿到会话。已登录其他账号的浏览器会先提示确认切换。
- 邀请和 River 发信任务在同一事务内写入。任务参数只有邀请 ID，投递时生成 256 位随机令牌，数据库只存哈希。链接自投递起 7 天内有效，令牌放在主站链接的片段中，由前端取出后 POST 兑换会话。已撤回、已首次登录（含验证码登录）、已停用或已过期的链接统一返回 410。链接过期后，仍受邀的邮箱可在登录页用验证码登录。
- 同一邀请在链接有效期内只发一次；链接过期且未使用时，重复邀请会补发一封新链接（只看邀请本身的状态，回答与对方是否有账户无关）。撤回后重新邀请会生成新链接，同一邮箱一小时内最多收到一封邀请邮件。
- 每次邀请都计入名额，包括邀请已有账户的邮箱，回答也完全相同，所以邀请不会泄露某个邮箱是否注册过；只有重复邀请自己邀请过的邮箱不计数。已有的账户不会被改动（停用的仍是停用）。不能邀请自己。
- 邀请关系记在 `invites` 表：每次邀请一行（邀请人、邮箱、时间）；只有当这次邀请新建了账户时才记 `invitee_id`，这就是"由谁邀请"。删除账户时，带有该邮箱的邀请记录一并删除；该用户发出的邀请中，建了账户的保留（邀请人显示为"已注销的账户"），其余删除。
- 开放注册模式下不需要邀请，设置页不显示邀请卡片，接口返回 409。
- 邀请记录显示"待接受 / 已注册"：只有这次邀请新建的账户登录过才算已注册，邀请已有账户的邮箱永远显示待接受，所以状态同样不泄露邮箱是否注册过。
- 待接受的邀请可以撤回：删除这条邀请。已排队过邀请邮件的撤回后**不退还名额**（否则"邀请—撤回"循环可以不限量地向任意地址发信，挤占删除通知的日额度），`revoked_invites` 表记下邀请人和原邀请时间，不存邮箱；从未发过邮件的旧邀请撤回后仍退还名额。是否退还只看邀请是否排过队，与对方是否有账户无关。这次邀请建的账户若从未登录就一并删除；如果还有别人邀请过同一邮箱，账户转给其中最早的一条邀请，对方仍能登录。已注册的不能撤回（409）。撤回时先锁邀请人、再锁被邀请人的账户行；登录时也锁账户行，两者不会交错。

**公共邀请链接**（邀请制下）：管理员可以开一个公开链接，在一段时间内提供一定数量的注册名额，适合发到群里或公众号文章里。
- 只有管理员能创建（后台「邀请链接」页，或 `observer admin invite-link create -n <名额> -valid 72h -note …`）。创建时设定名额（1～100）和有效期（1 小时～30 天，后台提供 1 / 3 / 7 / 14 / 30 天），备注只给管理员看。开放注册模式下不能创建（409）。
- 链接形如 `/join#t=<令牌>`。令牌是链接 ID 加上 HMAC（密钥由 `SIGNING_KEY` 派生，不与快照签名共用），数据库不存秘密，后台随时可以再次复制。轮换 `SIGNING_KEY` 后所有邀请链接一起失效。
- 打开链接仍要用邮箱验证码证明邮箱归属，链接本身不能直接建账户。`/join` 是带邀请的登录页：先 `POST /auth/invite-link` 查询链接状态，有效时只显示到期时间，不显示剩余名额；请求验证码和登录时都带上 `invite_token`。令牌存在 sessionStorage 里，切到邮件 App 再回来刷新也不丢。已登录的浏览器会提示先退出登录。
- 带有效链接时，没有账户的邮箱也能收到验证码；已有账户收到的是普通登录码，回答完全相同，不泄露邮箱是否注册过。停用的账户照旧静默不发。
- **名额只在真正新建账户时扣除**：登录事务里先锁链接行，确认未撤销、未过期、仍有名额，再建账户并加一。已有账户通过链接验证只是普通登录，不检查链接，也不占名额。同时抢最后一个名额的，只有一个能成功。已用名额是计数器，注销账户不退还。
- **每个链接的发码上限**为 `max(3 × 名额, 10)`，防止链接流传出去后被用来向任意地址发信。带链接的请求不论邮箱是否有账户都计数；单个邮箱的发码限制没通过或发信失败时退还。达到上限后链接仍然有效，已发出的验证码照常可以注册，只是不再发新码：请求验证码返回 429"这个邀请链接能发送的验证码已达上限"（与邮箱无关，不泄露是否注册），页面保留验证码输入框；后台状态显示"验证码已发完"（`no_codes`），可以撤销，不再提供复制。
- **全站每日预算**：所有邀请链接发出的验证码合计每天（UTC，与服务商额度一致）最多占邮件额度的 30%（默认 30 封），全站当天用量到 90% 后也不再发，保证普通登录和删除通知有额度。带链接的请求不论邮箱是否有账户都走这份预算，预算用完时回答也相同（503），不泄露邮箱是否注册；这次请求不计入链接和该邮箱的发码次数。已有账号仍可在登录页正常登录。群里集中注册时可能要分几天完成。
- 过期、名额用完、已撤销、令牌无效统一返回 410，页面显示"邀请已失效"，并给出邮箱登录入口。撤销立即生效，已注册的账户不受影响；链接记录保留，不删除。
- 来源分开记录：私人邀请记在 `invites`，公共邀请记在 `users.invite_link_id`（`invite_links` 表）。后台账户列表的「来源」列和详情的「来源」显示"公开邀请「备注」"（没有备注时显示创建日期）或邀请人邮箱；详情里点击后只看这个链接注册的账户（`/admin/users?invite_link=<id>`）或邀请人的账户。
- 开放注册模式下 `/join` 直接转到登录页，接口忽略令牌。

### 6.2 提交文章

1. `POST /api/v1/watches {url}` → 预规范化、校验域名。
2. 命中 `url_aliases` 且文章状态为 `alive`：直接创建 `active` 观察，返回 201。
3. 否则创建 `resolving` 观察，在同一事务内入队高优先级抓取任务，返回 202；前端轮询观察详情。
4. 抓取完成后：先把原始页面存入对象存储；再在一个事务内确定规范 ID → 合并或创建文章 → 观察转为 `active`（或 `failed`）→ 入队快照任务。快照任务异步读取原始页面、下载图片并生成阅读版，所以观察可能比快照早几秒到几十秒生效，前端显示"备份中"。
   - 同一用户用两种链接提交了同一篇文章时，合并后只保留一个观察，多出来的 `resolving` 观察会被删除。轮询到已删除的观察时，API 返回该用户对同一文章的现有观察。
5. 配额：每用户最多 50 个活跃观察，每日最多提交 30 次（可配置），管理员不限。提交在同一用户的行锁下依次完成查重、配额校验、创建和入队，并发请求不会一起越过上限；提交已在观察的文章直接返回原观察，不受配额限制。重新观察（§6.5）同样在用户锁下检查同时观察上限。

### 6.3 抓取与快照生成

1. 用 HTTP 客户端抓取页面（移动端 UA，每次任务内 UA 固定，自动 gzip，10 秒超时，**只允许请求白名单域名**，重定向后再次校验）。
2. 检测结果为 `blocked` 时按 §5.5 退避重试，不在服务器上换用浏览器。
3. 解析：标题、公众号名、作者、发布时间、正文节点 `#js_content`。
4. 下载图片：`data-src` 优先，带 `Referer: https://mp.weixin.qq.com/`，串行下载，单图 20 秒超时、上限 20 MB；计算 sha256，Wasabi 中已存在则跳过上传。图片格式按响应的 `Content-Type` 保存。
5. 清洗正文：移除脚本、事件属性、追踪像素；视频/音频 iframe 替换为占位卡片（附原链接）；图片地址改写为 `snap.<domain>/a/<sha256>`。
6. 生成阅读版 HTML（内置简洁样式模板，含标题、公众号、发布时间、原文链接、备份时间），上传到 Wasabi。
7. 同时上传原始 HTML（gzip），以便日后解析逻辑改进时重新处理。
8. 部分图片下载失败时快照仍然生效，记录 `missing_assets`，后续检查时补抓缺失图片。
9. **抓取记录 `captures`**：原始页面存入对象存储后，在入队快照任务的同一事务里登记一行（原始页面的键、快照 ID、文章链接、抓取时间、状态 `pending`）。快照生成成功时与快照同一事务标为 `done`；页面没有正文区域（`#js_content`，图片、视频消息）时立即标为 `failed / no_content`；其他错误在最后一次重试失败后标为 `failed / error`。
   - 理由：检测器允许"文章模板、有标题但没有 `#js_content`"的页面判为在线（`article_template_no_content_node`），快照生成却要求正文节点；重试用尽（如对象存储长时间不可用）也会让观察停在"正在备份"，而原始页面的位置只存在于任务参数里，无法补救。
   - 观察详情返回 `backup_status`（`none` / `pending` / `ready` / `failed`）和 `backup_error`，前端据此显示"正在备份"或失败原因。
   - 管理员在文章详情的"抓取记录"里看到每次抓取的结果，失败的可以**从已保存的原始页面重建**（`POST /admin/captures/{id}/rebuild`），不访问微信，文章已删除也可以；重建时记下 `captures.rebuilt_at`，历次备份据此标明来源是"抓取"还是"原始内容重建"。重建任务带上重建时间参与去重，以免被当成上一次（River 可能还没标记完成的）同一快照任务而丢弃；"重新备份"（重新抓取）只用于在线文章。有失败抓取的文章在"有问题"中标为"备份失败"。
   - 图片、视频消息的阅读版尚未支持，需要先采集样本；支持后可对这些失败的抓取逐一重建。

### 6.4 查看与下载

- **在线查看**：前端调用 `POST /api/v1/snapshots/{id}/view-url` 获取签名链接（HMAC，1 小时有效），以 `<iframe sandbox>` 嵌入 `snap.<domain>/s/<id>?sig=...`。
- **下载单文件 HTML**：快照服务在请求时把图片内联为 data URI，流式输出，不缓存成品（`snapshot.SingleFile`：先查齐所有图片的类型，缺图时在发送前就报错；之后逐张读取、边读边 Base64 编码写出，内存占用与图片大小无关；中途出错则断开连接，浏览器显示下载失败而不是保存半个文件）。同时最多 2 个下载，其余最多排队 15 秒，仍满则返回 503。命令行 `admin export` 用同一实现。
- **保存为 PDF**：阅读版 HTML 内置打印样式（分页、图片适配纸宽、隐藏无关元素、页脚标注原文链接与备份时间）。用户点击"打印 / 保存为 PDF"后，前端在新标签页打开快照，并提示使用浏览器的打印功能（iOS、安卓需从系统浏览器打开，微信内置浏览器不支持打印）。服务器不生成 PDF。
- 资源 `/a/<sha256>` 内容不可变，设置长期缓存头。读取顺序为 本地磁盘缓存 → Wasabi，回源后写入缓存。计划改为在线查看时图片直连 Wasabi（§8.1，待实施），`/a/` 保留作回退。

### 6.5 观察到期与收尾

周期任务（每 10 分钟）将超过 `expires_at` 的观察标记为 `ended(expired)`（不发邮件，见 §5.6）；文章不再有活跃观察时转为 `dormant`。

**续期**：`POST /watches/{id}/renew` 把观察的结束时间设为"从现在起 60 天"（`WATCH_DAYS`）。
- 观察中的：直接延长（只会往后推）。观察详情页在延长至少能多出一天时显示"延长观察"。
- 已到期或已停止、且文章仍在线（`alive` / `dormant`）的：重新变为观察中，清掉结束原因与通知标记；文章若已 `dormant`，恢复为 `alive` 并立即检查一次。详情页显示"重新观察"。这会占用同时观察的名额（超出返回 429），但不计入每日提交次数。管理员不受名额限制。
- 不能续期：文章已删除或失效、提交失败、正在解析；或者用户之后又提交了同一篇文章，已有另一条观察在进行（返回 409）。
- 是否可以续期由 `watch.Renewable` 判断，API 在观察上返回 `can_renew`，前端据此显示按钮。
- 不发到期提醒邮件（节省邮件额度）；列表中最后 7 天显示"还剩 N 天到期"，详情页显示剩余天数。不限续期次数。

### 6.6 金丝雀检测

周期任务（每 6 小时）检查一组配置好的金丝雀链接（`CANARY_ALIVE_URL`、`CANARY_DELETED_URL`）：一篇长期存在的文章和一篇已确认删除的文章。结果与预期不符时立即告警。这样微信页面结构变化会在第一时间暴露，不会等到用户反馈。

### 6.7 公众号入口（订阅号被动回复）

用户在个人订阅号的对话里发送文章链接即可开始观察。开启消息推送后，微信把用户消息 POST 到 `/wechat/callback`，我们在 5 秒内返回一条文本回复。只用被动回复，不调用任何需要 access_token 的接口（客服消息、模板消息都不用），因此不需要 AppSecret、IP 白名单或企业主体；也因此**不能主动推送**。绑定邮箱后，删除通知会发邮件，也会在用户下次给公众号发消息时随回复送达。实现在 `internal/mp`，绑定的业务规则在 `internal/auth/wechat.go`。平台配置步骤见 [runbook.md](runbook.md#公众号入口)。

**协议**：明文模式（全程 HTTPS，签名已能防伪造，不需要 AES）。校验 `signature = sha1(sort(token, timestamp, nonce))`（常量时间比较）且时间戳与服务器相差不超过 10 分钟；配置了 `WECHAT_ACCOUNT_ID` 时核对 `ToUserName`；请求体上限 64 KB。整个处理限时 4 秒，超时或出错回复"系统繁忙，请稍后再试"；没有回复时返回 `success`。微信 5 秒内没收到回复会重试 3 次，同一 OpenID 的相同 MsgId（事件按 OpenID、CreateTime 和事件类型）同时到达时共用一次处理，成功的回复在内存缓存 1 分钟，供重试原样取回。每个 OpenID 30 条消息的令牌桶，每 20 秒补 1 条，超出回复"发送太频繁"。日志只记 OpenID 哈希的前 8 位。

**消息与回复**（文本里用 `<a href>` 链接，单条不超过 2048 字节）：
- 关注：欢迎语与用法；未绑定时附绑定链接。取消关注事件不受消息频率限制，删除绑定和该 OpenID 的全部链接，不回复。停用账号仍可解绑，其他指令只回复"这个账号已停用"。
- 文章链接（文本中提取，与前端 `extractLink` 规则相同；或"链接"类型消息）：未绑定时暂存链接并回复绑定链接，绑定后自动开始观察；已绑定时调用 `watch.SubmitLink`，按结果回复"正在备份""已开始观察《标题》，到某日结束""已经在观察中""已经被删除（页面显示：…）""链接打不开"、配额提示或"账号已停用"，并附观察页链接。
- 整条消息为「我的」/「列表」：绑定的邮箱（打码）、观察中数量、最近 5 条观察（状态用设计规范的词），按字节预算截断。「绑定」「解绑」各司其职；其他内容和图片、语音等回复用法说明。菜单点击等其他事件不回复。
- **公众号与网站的关系**：公众号名（`WECHAT_NAME`）与网站名（`SERVICE_NAME`）不同时，回复写"本号配套的「网站名」网站"，绑定页与从绑定链接进入的登录页也写明"「网站名」是公众号「公众号名」配套的文章备份网站"，避免用户以为被引到了别的平台。带链接的回复末尾都附一句：链接打开的是本号配套的网站（主机名），微信可能提示"该网站未完成ICP备案"，可以放心继续访问。
- **邀请制下**：未受邀的邮箱收不到验证码（为不泄露邮箱是否注册，静默不发），所以给未绑定用户的回复写明"网站目前仅限受邀用户使用。已有账号或收到过邀请邮件的，请先绑定邮箱"。这说的是整体规则，不涉及任何具体邮箱。登录页在邀请制下不写"第一次使用会自动创建账号"。
- **发链接后等首次抓取**：新文章的观察处于 resolving 时，回复最多再等 3 秒（且至少在 4 秒处理时限前 1 秒停下），每 250 ms 查一次：抓取完成就直接回复"已开始观察《标题》"或打不开的原因；若这只是用户已在观察的文章的另一个地址（resolving 记录被合并删除），回复"已经在观察中"；仍未完成就回复"正在备份"，进度链接打开「我的观察」，避免合并后临时观察 ID 失效。首次抓取已被作者删除或违规下架的文章，回复微信页面给出的原因。生产上首次抓取通常 2–4 秒。
- **删除提醒随下一条回复送达**（`watches.wechat_told_at`）：公众号不能主动推送，所以已绑定用户下次发任何消息（「解绑」除外，停用账号除外）时，回复开头列出绑定之后、最近 30 天内在观察期间确认删除的文章（最多 3 条），各附备份链接。提交一篇早已删除的文章不会产生新的公众号提醒。命令回复和链接都准备好后才标记已告知，并发回复只包含各自成功标记的提醒。邮件照常发送，两者互不影响。
- 网站首页「怎么用」与设置页未绑定时显示公众号二维码（`web/public/wechat-qr.jpg`，只在开启公众号入口时显示；换图需要重新发布）。

**链接与令牌**（`wechat_tokens`，256 位随机数，只存哈希，一次性）：
- 绑定链接 `/wx/bind#t=<令牌>`，30 分钟有效，记 OpenID 和暂存的文章链接。网页上未登录先登录（登录页 `next=/wx/bind`），确认页写明当前邮箱和绑定的后果，可"换一个账号"。绑定在一个事务里完成：读出令牌 → 锁用户行 → 用咨询锁锁 OpenID → 消耗令牌 → 删掉该 OpenID 或该用户原有的绑定及旧的免登录链接 → 写入新绑定。暂存的文章随后用第二个事务提交，失败时绑定保留，页面显示原因；文章还在首次抓取时成功页只给「我的观察」入口，不链接临时观察 ID（它可能被合并删除，与公众号回复同一规则）。
- **加锁顺序**：绑定、免登录、网页解绑、公众号解绑 / 取消关注、删除账号一律按"用户行 → OpenID 咨询锁 → 绑定行 → 令牌行"加锁，避免死锁。绑定和免登录先不加锁读出令牌，得知用户和 OpenID 并加锁后再消耗令牌；公众号解绑不涉及用户行，从 OpenID 锁开始。
- 免登录链接 `/wx/go?to=<站内路径>#t=<令牌>`，24 小时有效，只能登录这个 OpenID **当前**绑定的账号（兑换时在事务里核对绑定）。同一条回复里的链接共用一个令牌：第一次点击登录，之后令牌已用，页面发现已登录就直接打开 `to`，否则去登录。
- 令牌放在 `#` 之后：浏览器不把它发给服务器，不进服务器与 Caddy 日志、不进 Referer、不会被预取消耗。页面读到后立即从地址栏去掉，暂存在 sessionStorage，再 POST 兑换。代价（已接受）：把回复转发给别人，对方能在有效期内用它登录一次，或把发送者的微信绑到自己的账号；确认页明示邮箱，公众号里发「我的」会显示绑定的邮箱。

**绑定关系**（`wechat_bindings`）：一个 OpenID 对一个账号，一个账号对一个 OpenID。解除绑定可在设置页或公众号里发「解绑」；取消关注、删除账号时一并删除。

**风险**：域名没有 ICP 备案。真机验证：微信内置浏览器会先显示"该网站未完成ICP备案，无法确认其安全性"，可以继续访问，绑定与免登录链接都能用；回复里因此附了说明。若将来被完全拦截，后备方案是"网页端绑定码"（设置页显示一个码，用户发给公众号完成绑定），尚未实现。

- 删除账号时级联删除会话、观察与公众号绑定；文章与快照属于公共备份，不随用户删除。

## 8. 对象存储设计（Wasabi）

```
assets/<sha256 前 2 位>/<sha256>          图片（不可变，内容寻址）
snapshots/<snapshot_id>/page.html        阅读版 HTML（图片引用为 /a/<sha256>）
snapshots/<snapshot_id>/raw.html.gz      原始页面
backups/postgres/<YYYY-MM-DD>.dump       数据库备份（pg_dump custom 格式）
```

- Bucket 私有，只由 app 访问，用户不直连 Wasabi。计划让图片改为直连（§8.1，尚未实施）；阅读版、原始页面、数据库备份始终私有。
- **90 天最短存储期**：除数据库备份外，所有对象都是长期保留，不受影响；数据库备份保留 120 天。**不要把 Wasabi 当临时存储用**，临时文件只放本地磁盘。
- 本地磁盘 LRU 缓存上限 5 GB（`CACHE_MAX_BYTES`），存放热点图片与快照 HTML，只在快照域读取时用到。
- 开发与测试用本地目录（`BLOB_DIR`）代替 S3，代码路径相同；S3 实现另有一个连真实 bucket 的测试（`TestS3`，需设置 `TEST_S3_*`）。
- Region 选 **新加坡 `ap-southeast-1`**：从香港 VPS 实测连接耗时 34 ms，是所有区域中最低的（东京 55 ms，Wasabi 没有香港区域）。程序使用专用子用户的密钥，策略只允许访问本服务的 bucket。
- 从 VPS 实测：64 KB 对象（接近文章图片大小）上传中位数 48–69 ms、下载 76–101 ms，一篇 55 张图的文章串行上传约 3–4 秒。

### 8.1 图片直连 Wasabi（已决定，待实施）

**起因**：文章浏览的流量几乎全是图片（一篇几 MB，阅读版 HTML 只有几十 KB）。图片现在全部经 VPS 转发：VPS 到大陆的线路带宽有限，并发时互相拥塞；据实际使用，大陆直连 Wasabi 取图明显快于经 VPS。

**出站配额不是问题**：同一 Wasabi 账号下其他应用已有接近 1 TB 的存储量，公平使用条款按账号的存储量比较，本服务的图片出站远低于此。

**方案**：
1. **Bucket 策略**：只给 `assets/*` 开放匿名读（`s3:GetObject`），`snapshots/`、`backups/` 保持私有；不开放列举。图片按内容哈希命名、地址固定，浏览器缓存可以长期生效。已接受的代价：知道哈希的人都能取到该图片（这些本来就是公众号的公开图片）。下架时删除对应对象即可。
2. **配置 `ASSET_BASE_URL`**（如 `https://s3.ap-southeast-1.wasabisys.com/<bucket>/assets/`）：设置后，快照服务在返回阅读版（`GET /s/{id}`）时把 `/a/<sha256>` 改写为 `ASSET_BASE_URL` 下对应的 `<sha256 前 2 位>/<sha256>`；不设置时保持现状。已存的 `page.html` 不改，回滚只需删掉这个配置。Wasabi 不支持自定义域名加 HTTPS，所以只能用 Wasabi 自己的域名。
3. **CSP**：快照页的 `img-src` 加入 `ASSET_BASE_URL` 的源。快照页已有 `<meta name="referrer" content="no-referrer">`，带签名的快照链接不会通过 Referer 泄露给 Wasabi；实施时补一个响应头 `Referrer-Policy: no-referrer` 双重保险。
4. **缓存头**：新上传的图片在 `PutObject` 时带 `Cache-Control: public, max-age=31536000, immutable`。已有图片没有这个头，浏览器会按启发式缓存；需要的话用一次性的原地复制补上元数据（覆盖会产生少量 90 天最短存储期的费用，可以忽略）。
5. **不变的部分**：`/a/<sha256>` 路由保留（作为回退，以及 `ASSET_BASE_URL` 未设置时使用）；单文件下载与 `admin export` 仍在服务器端从 Wasabi 读取并内联；阅读版 HTML 仍经快照域加签名提供。本地磁盘缓存此后主要缓存阅读版和下载时用到的图片，可以视情况调小 `CACHE_MAX_BYTES`。
6. **局限**：快照页禁止脚本，浏览器里没法"直连失败再走服务器"，只能整体开关。VPS 仍是单点：阅读版、签名链接、API 都在它上面，直连只减轻它的带宽压力。

**实施前后验证**：上线前在大陆网络（至少两家运营商）对同一张图比较 `snap.<domain>/a/<sha>` 与 Wasabi 直连的首字节时间和下载速度；上线后浏览器检查在线查看的图片来自 Wasabi、无 CSP 报错，下载与打印 PDF 正常；确认匿名请求 `snapshots/`、`backups/` 下的对象和列举 bucket 都被拒绝。

## 9. API（`/api/v1`，JSON）

完整契约见 `/api/v1/openapi.json`（或 `observer openapi`），前端类型由它生成。下表列出各接口的用途和非常规的状态码。

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/auth/code` | `{email, invite_token?}` → 202 `{remaining, resend_after}`；超限 429（含邀请链接的发码上限）；邀请链接已失效 410；当日邮件额度或邀请链接的验证码预算用完 503 |
| POST | `/auth/verify` | `{email, code, invite_token?}` → 设置会话 Cookie；通过邀请链接注册时名额已满或链接已失效 410 |
| POST | `/auth/invite-link` | `{token}` → `{expires_at}`；公共邀请链接已失效 410，开放注册 409（§6.1） |
| POST | `/auth/accept-invite` | 用邮件中的 `{token}` 完成首次注册，设置会话 Cookie。链接失效返回 410 |
| GET | `/auth/session` | 当前登录用户（同 `/me`）；未登录时返回 200 且无用户，前端启动时用它，避免访客页面出现 401 报错 |
| POST | `/auth/logout` | 注销当前会话 |
| GET | `/me` | 当前用户信息与设置，含本月通知邮件数与上限 |
| DELETE | `/me` | 删除账号（同时从验证码记录、发信记录和邀请记录中抹去邮箱） |
| GET / POST | `/invites` | 我发出的邀请与本月名额 / `{email}` 邀请 → 201；名额用完 429，开放注册时 409（§6.1） |
| DELETE | `/invites/{id}` | 撤回待接受的邀请 → 204；已注册 409（§6.1） |
| POST | `/watches` | `{url}` → 201（已备份）/ 202（解析中） |
| GET | `/watches` | 列表，支持 `status` 过滤，游标分页 |
| GET | `/watches/{id}` | 详情（含文章状态、最近检查记录、快照列表、备份状态 `backup_status` / `backup_error`） |
| DELETE | `/watches/{id}` | 停止观察 |
| POST | `/watches/{id}/renew` | 续期（§6.5）；超出同时观察上限 429，不能续期 409 |
| POST | `/snapshots/{id}/view-url`、`/download-url` | 返回签名的在线查看 / 单文件 HTML 下载链接 |
| POST | `/wechat/login` | `{token}`：用公众号回复里的免登录链接登录；已用、过期或绑定已变 410 |
| POST | `/wechat/bind` | `{token}`：把绑定链接对应的微信绑到当前账号 → `{submitted?, watch_id?, submit_error?}`；失效 410 |
| DELETE | `/me/wechat` | 解除公众号绑定 |
| GET | `/site` | 公开的服务设置（服务名、注册模式、观察天数、验证码次数、版本号、公众号与工具集信息），前端登录前使用 |
| GET | `/healthz` | 健康检查（DB 可用、worker 心跳） |
| * | `/admin/*` | 管理后台（§10.1）：概览、账户、邀请链接、文章、重新备份、从原始页面重建；非管理员 403 |

- **鉴权**：Web 使用会话 Cookie；未来小程序在 `Authorization: Bearer` 中携带同一种会话 token，共用 `sessions` 表。
- **CSRF**：会话 Cookie 使用 `SameSite=Lax`；所有写操作要求 JSON Content-Type，跨站请求按 `Origin` / `Sec-Fetch-Site` 拒绝。
- **错误格式**：RFC 9457 Problem Details（Huma 默认支持）。
- 没有开启公众号入口时 `/wechat/*` 接口返回 404。公众平台的回调 `GET / POST /wechat/callback` 返回 XML，不走 Huma（§6.7）。
- 快照域 `snap.<domain>`：`GET /s/{snapshot_id}?sig=...`、`GET /s/{snapshot_id}/single.html?sig=...`、`GET /a/{sha256}`。
- 主域上 `/api/` 以外的路径都由内嵌的前端提供（`internal/webui`）：带内容哈希的 `/assets/*` 长期缓存，其余路径返回 `index.html`（`no-cache`，附严格 CSP）。

| `/settings` | 设置 | 邮箱、退出登录、本月通知邮件数与上限、微信公众号绑定、邀请朋友（邀请制下）、删除账号（在确认弹窗输入当前账号邮箱） |
| `/about`、`/privacy`、`/terms` | 关于 / 隐私说明 / 服务条款 | 静态页（按需加载）；关于页末尾显示当前版本，正式版本链接到对应标签的源代码 |

- 状态标签只用设计规范的词：观察中、即将到期、已结束、已删除、无法访问，以及备份中。时间一律 24 小时制，当天 `HH:mm`、跨天 `MM-DD HH:mm`、完整日期 `YYYY-MM-DD`；图标为内联 Lucide（`ZgIcon`）。
- 技术：Vue 3 + vue-router + TypeScript，原生 CSS（浅色 / 深色跟随系统），不引入组件库。生产包脚本约 60 KB、样式约 9 KB（gzip）。
- 移动端优先：大部分用户在微信内置浏览器或手机浏览器中使用。桌面双栏在手机上改为单栏。构建目标兼容 Chrome 87 / Safari 14（较旧的微信内置浏览器）。
- 得意黑只用于我们自己的标题，完整字体（约 1.1 MB，`web/fonts/`，不打包）按界面文字裁成子集（约 80 KB）。改了界面文字后运行 `make web-fonts`（需要 fonttools 与 brotli）；`tests/font.test.ts` 在有字符没进子集时失败。来自别处的标题（自定义服务名）缺字时逐字回退到系统字体。
- 构建：`make web` 用 Vite 构建到 `internal/webui/dist/app`，`go build` 时通过 `go:embed` 嵌入；没构建前端的二进制在页面路径返回 503 提示。
- 主域 CSP：`default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:; connect-src 'self'; frame-src <快照域>; object-src 'none'; base-uri 'none'; form-action 'self'; frame-ancestors 'none'`，不需要任何 `unsafe-*`。
- 会话过期时，任何 API 请求返回 401 都会把用户带回登录页，登录后回到原来的页面（只允许站内路径）。
- 所属工具集：设置 `TOOLKIT_URL` 与 `TOOLKIT_NAME` 后，页脚版权行写"© 年份 服务名 · 工具集名 成员"（工具集名链接到主站，当前标签页打开），关于页末尾加「更多工具」一节，404 页加一句去工具集看看。没设置时（自行部署的默认情况）版权行写"开源项目，可自行部署"，其他两处不显示。顶部导航、快照、阅读页、邮件和管理后台都不放这个链接。

## 11. 抓取与检测（最大技术风险）

### 11.1 实测结论

2026-11-19 在大陆家庭宽带和香港 VPS 上用 `observer probe` 实测（纯 HTTP，不依赖浏览器），之后陆续补充样本：

- **香港 IP 可用**：同一篇文章每 3 秒检查一次、连续 100 次全部 alive，没有出现验证页。验证页目前只由"长链缺 `chksm`"触发，已在链接规范化中处理（§5.2）。因此不需要本地抓取节点，保留为预案（§11.3）。
- **页面特征**（样本在 `internal/wechat/testdata/`）：

  | 页面 | 大小（解码后 / 传输） | 识别特征 | 判定 |
  |---|---|---|---|
  | 正常文章 | ~4 MB / ~880 KB | `#js_content` 有内容；头部 ~18 KB 处有 `og:type=article`、`og:title`、`og:url` | alive |
  | 作者删除 | ~32 KB / ~16 KB | `.weui-msg__title` = "该内容已被发布者删除"；通用页面，没有标题和 Open Graph 标签 | deleted / author_deleted |
  | 违规（含接投诉后判违规） | ~32 KB / ~16 KB | 标题"此内容因违规无法查看"；说明里的"投诉"二字不影响分类 | deleted / violation |
  | 验证页 | ~17 KB / ~13 KB | 跳转到 `/mp/wappoc_appmsgcaptcha?poc_token=...`，`PAGE_MID='mmbizwap:secitptpage/verify.html'` | blocked |

- **仍缺**侵权投诉（`complaint`）、账号封禁 / 迁移的真实样本；规则中已按关键词预留分类，并有合成样本测试。
- **`PAGE_MID` 赋值语句出现得很晚**（~0.7 MB 处），所以页面头部判断只能依靠 Open Graph 标签；删除页和验证页都没有这些标签。`head` 方式只能拿到标题和 `og:url`，首次抓取必须用完整页面。
- **提前停止读取**：HTTP/2 接收窗口设为 16 KB 时，`check` 约 210 KB、`head` 约 26 KB；窗口 128 KB 时服务端会多推送数据（242 / 58 KB）。默认窗口取 16 KB。
- **图片**（`mmbiz.qpic.cn`）带不带 Referer 都能下载；实现上仍带 Referer 并保持会话内 UA 一致。三种 UA 预设（ios / android / desktop）都能正常拿到页面。

### 11.2 检测实现原则

- 判定规则按"强信号优先"：先识别验证/拦截页（`blocked`），再识别删除提示页（`deleted`），最后要求正文节点存在且非空才算 `alive`。**三者都不满足时归为 `error`，绝不默认判为 `alive`**。
- 规则集中在 `internal/wechat/analyze.go`，每条规则都有对应的样本测试。
- 样本文件放在 `internal/wechat/testdata/`，用 `observer probe -save-fixture` 采集并脱敏（去掉 token、追踪参数），再精简后入库。
- 正文在 `div#js_content`，图片真实地址在 `data-src`。清洗时保留 DOM 结构，不逐段抽取文本（旧实现因嵌套 `section` 重复提取正文）。
- 金丝雀检测（§6.6）兜底发现规则失效。

### 11.3 被拦截严重时的预案（按成本递增）

1. 降低频率、加大间隔与抖动、调整请求头。
2. **本地抓取节点**：在家用宽带的机器上运行 `observer agent`（尚未实现），通过鉴权 API 从服务器领取被拦截的抓取任务并回传结果，借用住宅 IP。服务器仍然只跑后端；节点离线时任务继续排队，不影响其他功能。如果拦截基于浏览器特征而不是 IP，本地节点可以带上 Chromium。
3. 用户侧补充：提供书签脚本或浏览器扩展，由用户的浏览器抓取页面后上传。
4. 付费代理（最后手段，需要重新评估成本）。

## 12. 安全与合规

- **快照隔离**：快照是第三方内容，只在 `snap.<domain>` 提供，该域不设置任何登录 Cookie。响应头：
  `Content-Security-Policy: sandbox allow-same-origin allow-popups allow-popups-to-escape-sandbox; default-src 'none'; img-src 'self' data:; style-src 'unsafe-inline'; frame-ancestors https://<domain>`。
  此外，入库前已经过 bluemonday 清洗。图片改为直连 Wasabi 后（§8.1），`img-src` 还要加入 `ASSET_BASE_URL` 的源。
  `allow-same-origin` 是必需的：没有它，快照页会变成匿名来源（opaque origin），它对 `/a/` 图片的请求就成了跨源请求，会被图片的 `Cross-Origin-Resource-Policy: same-origin` 拦截。它只在**禁止脚本**的前提下安全，绝不能再加 `allow-scripts`；测试会检查这一点。前端 iframe 的 `sandbox` 属性同样如此设置。
- **SSRF 防护**：抓取只允许白名单域名，页面只允许 `mp.weixin.qq.com`，资源只允许 `*.qpic.cn`、`*.qlogo.cn`、`res.wx.qq.com`。拨号时拒绝内网、回环、链路本地、CGNAT 等非公网地址，重定向后再次校验（`internal/wechat/fetch.go`）。
- **签名链接**：HMAC-SHA256，密钥来自配置，带过期时间；签名绑定快照 ID。
- **会话安全**：token 只存哈希；Cookie 使用 `__Host-` 前缀；可以注销全部会话（`admin logout-all`）。
- **滥用防护**：登录、提交接口按 IP 与用户限流；用户配额；注册模式 `REGISTRATION_MODE=open|invite`（默认 `invite`）；如有邮件轰炸，可加自托管工作量证明验证（如 ALTCHA），不依赖第三方验证码服务。
- **不泄露邮箱是否注册**：登录、邀请、邀请链接的所有回答对有无账户的邮箱完全相同（§6.1）。
- **密钥管理**：所有密钥放在服务器 `.env`（权限 600），不进仓库；代码中不硬编码任何邮箱、openid 或默认口令。
- **隐私**：只收集提供服务所需的信息，隐私说明页（`/privacy`）逐项写明用途与保存期限，必须与实现一致：
  - 验证码记录（含请求 IP）在过期一天后删除；每个邮箱的每日计数保存 2 天；会话（含 User-Agent）过期或退出后删除；发信记录保存 90 天（`auth.Cleanup` 每天清理）。
  - 删除账号：用户、会话、观察列表级联删除；该邮箱的验证码记录删除；发信记录中的地址改为 `deleted`（保留行用于当天额度计数）；每日计数照常 2 天后过期，避免删号重注册绕过限制。集成测试检查删除后任何表里都不再有该邮箱。
  - 服务访问日志不记录 IP 和查询参数。Caddy 不开访问日志，并且给所有日志加了过滤器：Caddy 自己的警告和错误（例如客户端中途断开时）会附带整个请求，过滤器删除其中的 IP、端口、请求头、TLS 信息和快照链接的签名参数。只关访问日志是不够的。
- **公众号入口**（§6.7）：只保存 OpenID（只在本公众号内有效）与绑定时间，不保存消息内容；回复里的一次性链接最长 1 天有效，过期后每天清理；解除绑定、取消关注、删除账号时立即删除绑定。微信回调的查询参数（`signature`、`timestamp`、`nonce`、`openid`、`echostr`、`msg_signature`）也由 Caddy 日志过滤器删除，应用日志只记 OpenID 哈希前缀。隐私说明页在开启公众号入口时显示对应条目。
- **版权与下架**：快照默认仅对观察过该文章的用户可见；提供联系方式处理下架请求。
- **HTTP 安全头**：主域设置 HSTS、`X-Content-Type-Options`、严格 CSP（Vue 构建产物不需要 `unsafe-eval`）。

## 13. 部署与运维

操作步骤见 [runbook.md](runbook.md)，这里只记设计。

### 13.1 Compose 服务与内存预算（1 GB 内存）

| 服务 | 镜像 | 容器上限 | 上线后实测 |
|---|---|---|---|
| caddy | `caddy:2-alpine` | 64 MB | ~28 MB |
| postgres | `postgres:18-alpine` | 320 MB | ~85 MB |
| app | `alpine` + `observer` 二进制 + `postgresql18-client`（备份用，§13.4），约 40 MB，非 root 运行 | 256 MB | ~41 MB |

- VPS 可见内存 913 MB，配置了 2 GB swap（`vm.swappiness=10`），journald 限制 100 MB。
- app 设置 `GOMEMLIMIT=200MiB`；图片下载按流处理，不在内存中整体缓存大文件；单文件 HTML 也以流式输出。
- Postgres 参数（`deploy/compose.yaml`）：`shared_buffers=96MB`、`effective_cache_size=256MB`、`work_mem=4MB`、`maintenance_work_mem=32MB`、`max_connections=30`、`max_wal_size=512MB`；pgx 连接池上限 10。
- 只有 caddy 对外开放 80/443（含 HTTP/3 的 443/udp）；app 与 Postgres 只在 Compose 内部网络通信。

### 13.2 磁盘规划（30 GB）

系统约 5 GB、镜像约 2 GB、Postgres 数据 < 2 GB、本地缓存上限 5 GB；容器日志设上限；部署后自动执行 `docker image prune`。

### 13.3 配置项（环境变量）

全部配置项及默认值见 `internal/config/config.go`，生产示例与说明见 `deploy/.env.example`。几条规则：

- `SNAP_BASE_URL` 必须与 `BASE_URL` 不同主机。
- `BASE_URL` 为 https 时视为生产环境：`SIGNING_KEY`、`SMTP_HOST` 必填，`SNAP_BASE_URL` 也必须是 https；开发环境缺少它们时，分别退化为随机签名密钥、只把邮件写进日志。
- `SIGNING_KEY` 用于快照链接签名，也用于派生公共邀请链接的令牌，轮换后两者都失效。
- 设置 `S3_BUCKET` 时使用 S3，否则使用 `BLOB_DIR`；两者至少设置一个。
- `WECHAT_TOKEN` 设置了才开启公众号入口；`TOOLKIT_URL` 设置了才显示工具集链接（此时 `TOOLKIT_NAME` 必填）。
- env 文件按 Docker Compose `env_file` 的格式书写（值不加引号，可含空格和 `<>`），`observer mailtest -env-file <文件>` 可直接读取。

### 13.4 备份与恢复

- 每天北京时间 03:30 由 River 周期任务执行 `pg_dump --format=custom`（自带压缩），先写临时文件再上传到 `backups/postgres/YYYY-MM-DD.dump`，保留 120 天（每次删除恰好过期的及之前 6 天的，覆盖偶尔漏跑的日子）；失败时告警。只在配置了 S3 时启用。连接信息通过 `PG*` 环境变量传给客户端工具，密码不出现在命令行。
- `observer admin restore` 只恢复到空数据库，不会覆盖正在使用的库。
- 快照、图片本身就在 Wasabi 中，不需要另外备份。

### 13.5 监控告警

- `/healthz` 返回数据库连通性和 worker 最近一次心跳时间。
- 调度任务每轮完成后 ping Healthchecks.io；超时未 ping 时由 Healthchecks 发邮件告警。
- 应用内告警见 §5.6；日志为 slog JSON 输出到 stdout。

### 13.6 CI/CD

- **PR / push**：golangci-lint → `go test -race ./...`（CI 使用 Postgres 18 service container）→ sqlc 与 OpenAPI 生成代码的同步检查 → 前端 `vue-tsc`、Vitest 与构建。
- **tag `v*`**（`.github/workflows/release.yml`）：构建 amd64 镜像并推送 `ghcr.io/mamaship/observer:vX.Y.Z`；只有正式版本标签更新 `latest`，预发布标签（`v1.2.3-rc.1`）不动它。配置了部署密钥时，SSH 到 VPS 运行 `/opt/observer/update.sh vX.Y.Z`。部署密钥在服务器上用 `command=` 限定只能运行 `update.sh`，且只接受版本号格式的标签。`update.sh` 先备份数据库，再只更新 app 并等健康检查，失败自动回滚到原镜像。迁移在 app 启动时自动执行。
- Dependabot（`.github/dependabot.yml`）每月为 Go、npm、GitHub Actions、Dockerfile 与 compose 镜像各开一个汇总 PR；镜像不自动升级大版本（Postgres 18 → 19 需要数据迁移，且 app 镜像里的 `pg_dump` 版本要一起换）。安全更新由 GitHub 随时单独提出。
- Dependabot 不提 TypeScript 与 `@types/node` 的大版本：TypeScript 7 是原生重写版，`openapi-typescript` 要求 ^5、`vue-tsc` 也还不支持；`@types/node` 跟构建用的 Node 22。
- `minimatch`、`glob` 的安全警告只经 `@vue/test-utils` → `js-beautify` 进入开发依赖，不进生产构建；在 `web/package.json` 的 `overrides` 里只对 `js-beautify` 这一支升级。

| 集成 | store 查询、任务流程（提交 → 抓取 → 快照 → 删除 → 通知）、验证码登录与每日限制、邀请与绑定的并发、HTTP API 全流程（`internal/app/flow_test.go`）、公众号全流程（`internal/app/wechat_test.go`） | 真实 Postgres；blob 用临时目录、mailer 用内存实现；微信用 `watchtest` 按样本回放 |
| 邮件 | 模板渲染；SMTP 发送、额度拒绝识别、登录检查 | 进程内的假 SMTP 服务器；真实送达用 `observer mailtest -to` 手动验证 |
| 对象存储 | `blob` 的读写测试用本地目录实现；S3 实现用 `TestS3` 验证 | 设置 `TEST_S3_*` 时连真实 bucket 运行，否则跳过 |
| 前端 | 类型检查；工具函数、API 错误处理与页面组件测试（假 API） | `vue-tsc`、Vitest + happy-dom、`@vue/test-utils` |
| 浏览器验收 | `web/e2e/smoke.mjs`：真实 Chrome、手机尺寸，从登录到打印 PDF 走完整流程，检查控制台错误、CSP 违规与 5xx | `playwright-core` + 本机 Chrome；需要真实微信，手动运行，不进 CI |
| 线上 | 金丝雀检测 | §6.6 |

- 需要数据库的测试读取 `TEST_DATABASE_URL`，未设置时跳过；`make test` 会启动本地 Postgres 并设置它。每个测试新建一个独立的临时数据库并在结束时删除，因为不同包的测试是并行运行的。
- 每个修复的线上问题都必须补充对应的样本或回归测试。

## 17. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 香港数据中心 IP 被微信频繁拦截 | 核心功能不可用 | 实测 3 秒一次、连续 100 次未被拦截，但微信策略可能变化；降频与熔断；金丝雀告警；本地抓取节点（住宅 IP）；用户侧抓取；最后才考虑付费代理 |
| 微信页面结构变化 | 漏报 / 误报 | 四态判定，不默认判为存在；样本测试；金丝雀检测与告警 |
| 1 GB 内存不足 | OOM、服务中断 | 服务器不运行浏览器；容器内存上限；流式处理大文件；swap |
| 用户不会用浏览器打印 PDF | PDF 体验差 | 页面内操作引导；单文件 HTML 始终可用；需求明确后再做服务端 Go 直出 PDF |
| Resend 每日 100 封限额 | 通知延迟 | 摘要合并；优先级；Snooze 到次日；80% 用量告警；SMTP 抽象层便于更换服务商 |
| 通知邮件被 QQ/163 判为垃圾邮件 | 用户收不到通知 | 已配置 SPF/DKIM/DMARC，Gmail、QQ 实测进收件箱（QQ 要求发件人域名本身有 SPF 记录）；纯文本风格、无营销用语；Web 端可随时查看状态 |
| 发件域名在 `.click` 顶级域名下 | 部分邮箱可能更严格 | 目前实测正常；关注 `email_log` 与用户反馈，进垃圾箱比例偏高时换用 `.com` 等域名专门发信（只需改 `MAIL_FROM` 与 DNS） |
| 验证码每天 2 次的限制 | 用户输错或没收到时当天无法登录 | 会话 60 天滑动过期，平时很少需要重新登录；登录页显示剩余次数与重发倒计时；管理员可用 SQL 清除 `login_requests` 中的计数 |
| 微信内置浏览器拦截未备案域名 | 公众号回复里的链接打不开，无法绑定 | 目前只有警告、可继续访问；后备方案为网页端绑定码（§6.7） |
| 大陆访问香港站点慢或不稳定 | 体验差 | 前端资源体积小、长缓存；图片直连 Wasabi（§8.1）；必要时评估 CDN |
| 滥用（邮件轰炸、批量提交） | 额度耗尽、资源耗尽 | 限流、配额、邀请制、邀请链接的发码上限与每日预算、PoW 验证（按需） |
| 单机故障 | 数据丢失 | 每日数据库备份到 Wasabi，文件本身已在 Wasabi；恢复手册与演练 |
| 版权或法律投诉 | 运营风险 | 快照默认私有；下架流程；服务条款 |
